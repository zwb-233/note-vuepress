nextjs

介绍

  • Next.js 是一个用于创建全栈应用程序的框架，它基于React，并添加了一些额外的功能，如新的路由、数据预取、混合渲染(SSR)方式

渲染方式

  • Next.js其实支持混合渲染，包括：
  • 客户端渲染(CSR)：在浏览器上处理数据，渲染首屏页面，并请求数据，需要提供较大的js文件来实现React基本特性、请求数据等功能，这也是最早出现的页面渲染方式
  • 服务端渲染(SSR)：在服务器上处理数据，渲染完整页面，并返回静态的首屏页面给用户，仅提供很少的必要js
    • 页面首屏加载快，页面加载不需要js处理的时间
    • 因为页面是完整返回的，对爬虫和搜索引擎更友好，实际上利于SEO
    • 虽然是静态页面，但数据保证是最新的，每次请求会重新渲染
    • 因为在服务端渲染，没有办法获取组件的生命周期，功能比客户端渲染少，一般是混合渲染

    页面初始内容由服务器渲染，之后可以加载React，让客户端渲染，这种混合方式也被称为Hydration(注水)

  • 静态生成(SSG)：在服务器上处理数据，渲染完整页面文件，之后请求每次返回完全一致的静态的页面文件，也就是首屏页面的内容是固定的，可以直接交给CDN缓存
    • 首屏加载非常快，但数据可能不是最新的
  • 增量的生成(ISR)：静态生成和SSR结合，在服务器上处理数据，渲染完整页面文件，之后定时生成新文件，比如每隔60s生成一次，这段时间内都返回相同的页面文件
    • 首屏加载和SSG一样，非常快，但数据可能也不是最新的

路由

路由的组织形式

app 路由方式

  • 文件路由：next.js的路由是直接通过文件路径定义的，整个项目的页面被放置在app文件夹下(即现在推荐的app路由)，文件完整路径名作为页面路由路径，文件组织形式要基于以下约定式路由
  • 在app目录中，每个文件夹对应一个路由段，映射到URL路径中的对应路径段，比如app/blog文件夹对应映射的URL路径是/blog
    • 虽然路由是公开的，但只有page.tsx和route.tsx返回的内容被允许发送给客户端，其他的文件可以安全地存放在路由目录内
    • 如果不希望文件夹中的内容被发送给客户端，可以在文件夹名前增加一个_，比如_lib，这样这个文件夹和其中的子文件夹会排除在路由外
  • 特定文件名

    • page.tsx：页面文件，对应一个具体的URL页面，用于生成该路由的主要内容，比如app/blog/page.tsx对应的子路由是/blog

    • layout.tsx：布局文件

      • 其中的函数有一个传入的只读children组件(来自其他布局文件或page.tsx，自动传入)
      • 如果应用是SPA，并且layout还需要展示，layout生成的结构就会复用，不会重新渲染，对于一些需要重新渲染挂载的组件骨架需要使用template.tsx，这是每次切换路由都会重新加载的布局文件，写法和layout相同
      • 页面的布局会先被layout.tsx包裹，再被template.tsx包裹
      • 布局会根据文件夹嵌套布局，比如app/blog/react/page.tsx文件的布局是被AppLayout、BlogLayout、ReactLayout嵌套的，最后内部包裹page.tsx的结构，如果还有Template.tsx，最终的/blog/react页面结构类似
      <AppLayout>
    <BlogLayout>
    <BlogTemplate>
        <ReactLayout>
        <ReactTemplate>
            <Page />
        </ReactTemplate>
        </ReactLayout>
    </BlogTemplate>
    </BlogLayout>
</AppLayout>

    • loading.tsx：加载状态组件。当页面或其子组件在获取数据或进行异步渲染时，Next.js会自动显示该组件。通常用于展示skeleton或loading UI

    • not-found.tsx：404页面。当页面调用notFound()或访问不存在的资源时会显示该组件

    • error.tsx：错误边界组件。当当前路由或其子组件在渲染过程中抛出错误时会显示该组件，用于处理服务器运行时错误

  • [slug]文件夹：动态路由参数，用于匹配URL中的动态部分，例如app/blog/[slug]/page.tsx，可以匹配/blog/任意名称，但不会捕获/blog/文件夹/路由名称这样的文件夹深度嵌套
    • 在页面组件中可通过params.slug获取该参数
  • [...slug]文件夹：类似[slug]的增强，能够捕获任意深度的子路径
    • 此时params.slug是一个数组，包含所有匹配路径，例如['blog', 'react', 'intro']
  • (markgroup)：路由分组，用于组织文件结构，不会影响URL路径，也就是说(名称)作为文件夹名称时，最终的页面路由中不会包含这个文件夹名称
    • 路由分组有利于创建多根布局，可以在每个组中创建layout，比如app/(overview)/layout.tsx、app/(admin)/layout.tsx，对于不同分组使用不同的根布局
  • @slot：并行路由插槽，用于在布局中同时渲染多个独立的路由区域，如果有app/blog/@slotName/page.tsx，就可以在app/blog/layout.tsx中接受到新的参数slotName，在布局中生成新区域，和page.tsx中的内容相互隔离
  • (.)/(..)：拦截路由语法，用于在当前布局中拦截并部分渲染其他路由，通常需要和@slot文件夹合用，渲染在@slot区域中
    • (.)：表示当前路由同级的页面内容，(..)表示是和父路由同级的内容
    • 例如app/gallery/@modal/(.)photo/[id]/page.tsx，实际上是支持将app/photo/[id]/page.tsx中的内容渲染在app/gallery/page.tsx中的@model区域中

样式

避免使用tailwind的@import指令

  • tailwind可以使用@import 'name.css'引入其他的样式文件，但nextjs不会识别这些引用关系，不会触发项目的重新编译
  • 如果在引入的样式文件中有tailwind语法错误，会导致缓存错误，对应文件不会重新编译，需要手动清除缓存.next才能编译得到正确的结果
  • 这个问题可以通过在jsx中引入所有需要的css来避免
